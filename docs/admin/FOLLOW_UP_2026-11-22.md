## How things ship (no Mac needed)

| What | How | Where the result is |
|---|---|---|
| Server + admin panel | push a commit to `ops-request` with `ops/REQUEST` (`ACTION=deploy`) — `.github/workflows/production-ops.yml` | log on branch `ops-log` (`logs/*-deploy-*.log`) |
| Other server actions | same, `ACTION=` `status` · `rollback` (ARG = release id) · `reset-dry-run` / `reset-apply` (ARG = cutoff) · `disk-report` · `cleanup` · `service-areas` (read-only diagnosis) · `maps-on` / `maps-off` | `ops-log` branch |
| Customer app (Android) | push to branch `app-build` — `.github/workflows/customer-app-build.yml` | GitHub → Actions → run → Artifacts (`.aab` for Play, `.apk` for phones) |
| Driver app (Android) | push to branch `driver-app-build` — `.github/workflows/driver-app-build.yml` | same |

Guide: `docs/launch/PRODUCTION_OPS_FROM_GITHUB.md`. Every deploy backs up + test-restores the database first, switches back by itself if the
backend is unhealthy, and tidies the disk (keeps the 3 newest releases).
